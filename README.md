# Bachata HUB Беларусь — слой 1

Агрегатор бачата-сцены Беларуси: единый календарь событий по всем городам,
каталог школ с отзывами и профиль танцора. Это первый, бесплатный слой
продукта — без приёма платежей, без судейства конкурсов и без продажи
билетов. Задача — собрать сообщество и данные.

Полное техническое задание: `Promt_layer1.md` в этой же папке.

## Стек

Next.js 15 (App Router, TypeScript) как единое full-stack приложение —
серверный рендеринг закрывает требование к индексируемости публичных
страниц без отдельного бэкенда; PostgreSQL + Prisma ORM — типобезопасная,
растущая без миграций «с нуля» под будущие слои 2 и 3; авторизация —
email/пароль на httpOnly-JWT-сессии; `docker-compose.yml` с двумя сервисами
(`app` + `db`) даёт запуск одной командой.

## Запуск

Нужен установленный [Docker](https://www.docker.com/) (Docker Desktop на
Windows/macOS, или Docker Engine + Compose plugin на Linux).

```bash
docker compose up
```

Первый запуск:

1. поднимается Postgres и ждёт готовности (healthcheck);
2. контейнер `app` собирается (может занять несколько минут — ставятся
   npm-зависимости);
3. применяются миграции Prisma (`prisma migrate deploy`);
4. если база пустая — наполняется демо-данными (см. ниже); при последующих
   перезапусках сидирование пропускается, чтобы не затирать то, что вы
   добавили через сайт;
5. сайт открывается на **http://localhost:3000**.

Если порт 3000 занят или нужны другие секреты сессии — скопируйте
`.env.example` в `.env` и поменяйте значения; `docker-compose.yml` подхватит
их автоматически (`NEXTAUTH_SECRET`, `SESSION_SECRET`, `NEXT_PUBLIC_SITE_URL`).

Локальная разработка без Docker (нужен свой Postgres):

```bash
npm install
cp .env.example .env   # укажите DATABASE_URL на свой Postgres
npx prisma migrate deploy
npm run seed            # наполнить демо-данными (можно повторять — upsert)
npm run dev
```

## Демо-данные

Скрипт `prisma/seed.ts` создаёт:

- 6 городов (Минск, Гомель, Гродно, Брест, Витебск, Могилёв);
- 5 школ в Минске с филиалами, преподавателями и расписанием групп — 3 с
  подтверждённым статусом («профиль подтверждён представителем школы»), 2
  «созданы сообществом»;
- 19 предстоящих событий в разных городах и форматах (вечеринки,
  мастер-классы, фестиваль, конкурс, интенсив) — 2 из них намеренно
  оставлены непроверенными, чтобы в очереди модерации сразу было что
  показать; плюс 5 прошедших (архивных) событий — специально для истории
  посещений в профилях;
- 28 профилей танцоров с отметками «был»/«иду» и отзывами на школы —
  большинство отзывов уже проверены модератором, один на каждую школу
  намеренно оставлен «на модерации» (демонстрация очереди и того, что автор
  видит свой отзыв ещё до публикации);
- 1 заявка на владение школой в статусе «на проверке» — демо очереди
  модерации.

## Путь пользователя: от регистрации до отметки события

1. **Регистрация** — `/register`: имя, e-mail, пароль, город, роль
   (танцор / представитель школы / организатор). Танцору сразу создаётся
   профиль.
2. **Календарь** — `/events`: фильтр по городу, формату, уровню, датам,
   школе. Карточка события открывается по клику.
3. **Отметка посещения** — на странице события кнопки «Иду» / «Был» (видны
   только вошедшим танцорам) пишут запись в `Attendance` с
   `source: SELF_REPORTED` — это декларативная история, ещё не подтверждённая
   оплатой (это придёт со слоем 2).
4. **Профиль** — `/profile`: история отметок и раздел «достижения»
   (заполняется вручную, поле `source` уже готово принимать `CONTEST_RESULT`
   от слоя 3 без переделки схемы).
5. **Школы** — `/schools`: отзыв публикуется только после проверки
   модератором (`moderationStatus: PENDING` по умолчанию) — до этого его
   видит только автор, с пометкой статуса на странице школы; заявка «я
   представитель школы» (`SchoolClaim`) уходит в очередь модератора и не
   публикуется сама.
6. **Модерация** — `/moderation` (только для роли `MODERATOR`/`ADMIN`):
   очереди событий, заявок на школы, отзывов; каждое решение пишется в
   `ModerationLog`; на главной странице модерации — три метрики роста
   (города с активными событиями, подтверждённые школы, танцоры с
   историей посещений).

```

```

## Дальнейшие шаги

- **База в облаке (Supabase / любой managed Postgres)**: миграция в
  `prisma/migrations/20260901000000_init/migration.sql` уже проверена и
  готова к применению — достаточно указать `DATABASE_URL` от Supabase и
  выполнить `npx prisma migrate deploy`.
- **Деплой**: `docker-compose.yml` рассчитан на любой хостинг с поддержкой
  Docker Compose (или два отдельных сервиса — Postgres и Node-приложение —
  на площадках вроде Render). Обсудим отдельно, когда база будет в Supabase.
- **Слой 2** (оплата, подтверждённая регистрация через ЕРИП/bePaid) и
  **слой 3** (судейство конкурсов, автоматические достижения) подключаются
  новыми таблицами и связями поверх текущей схемы — без миграции
  существующих данных, как и требовалось в ТЗ.
